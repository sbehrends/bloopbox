bloopbox Brand kit

Retro-Futurist Intercom — bold, playful, tactile, screenless.

A screenless box with three lit arcade buttons, for a two-year-old and the people who love them. The brand has to reassure a parent that the technology is playful rather than complex, and it has to be legible to a child who cannot read. Which is why the real work happens in colour, shape and light, not in words.

This page loads shared/tokens.css and shared/base.css — the same two files the setup portal, the admin panel and the simulator load. It is the design system, not a picture of it.

1 · Logo system

A rounded speech-bubble pill with a tail, drawn as line art: a yellow arc on the left, a teal arc on the right, a coral ring overlapping them in the middle, and three small ring buttons on the centre line. It carries the device's technical side (a message, a voice) and its physical one (three big tactile buttons) in one form, and the buttons are in the order they sit on the enclosure: yellow, coral, teal. Every interior is transparent, so the mark sits on the page rather than covering a piece of it.

bloopbox-iso-light.svg — black outline, for a light page

bloopbox-iso-dark.svg — white outline, for a dark page

bloopbox-favicon.svg — one file, it switches its own ink

The mark stops working below about 24px — the arcs, the outlines and the button holes all collapse into one blur, as the third figure shows. So there is a second drawing, bloopbox-favicon.svg, and it is the only one allowed: the same pill and tail, filled edge to edge with three flat colour fields, no inner outlines and no buttons, which is what survives in a browser tab. It is a different job, not a variant. Change the colours or the button order in one and change them in the other.

Display sizes only — amber on cream is 1.6:1, which is right for a logotype and wrong for anything that has to be read as text. Both grounds are pinned, so the pair is always side by side whichever theme you are reading this in.

The right-hand tile is a known-bad asset, shown rather than hidden. bloopbox-logo-dark.svg is not the light drawing with its outline reversed: the left arc is teal where it should be yellow, the three button rings are still black and so they sink into the navy, and an opaque white pill sits behind the whole thing where every other drawing keeps its interior transparent. It came from the site that way and it has to be fixed there, because the box copies that artwork path for path — see PENDING.md. A kit that quietly substituted the good file here would be the one place the defect could not be seen.

Chrome lockups

bloopbox
bloopbox Setup

Beside the mark, at chrome size, the wordmark is navy and the tag chip says which page you are on — the wordmark itself never changes to say "bloopbox Admin". It is always lowercase and always set, never drawn, so it stays selectable and scales with the type scale.

The mark's interiors are all transparent, so its outline sits directly against whatever is behind it and cannot be one fixed colour: black disappears into a navy page exactly as it needs to stand out on a cream one. So the mark ships as two files that differ in that one path — -light is inked black, -dark white — and a surface that follows the OS picks between them with <picture> and a prefers-color-scheme <source>. The lockup at the top of this page and the neutral tile above both do exactly that. bloopbox-favicon.svg is the one asset still doing it the old way, switching its own ink from an embedded <style> block, which it can afford because it is a solid drawing with a single ink.

<picture> reads the OS, not the element, so it is only right where the surface reads the OS too. Anywhere the colour is pinned, pin the file too and check it by eye: the teal tile beside it keeps the black-inked mark in both themes because the teal never moves, and §1's two size panels each pin the ground their drawing was inked for.

  • Do keep clear space around the mark equal to the width of one button.
  • Do pair the file with its ground: -light on cream, -dark on navy. On a surface that follows the OS, let <picture> choose.
  • Do pick the file by hand on any fixed-colour panel, and check it by eye. <picture> reads the OS and cannot see the tile it is sitting on.
  • Do use the favicon drawing below 24px, and the mark above it.
  • Don't recolour or reorder the buttons. Left to right is yellow, coral, teal, and that is which physical button each one is.
  • Don't use the amber wordmark on cream at text sizes. Navy in chrome, amber only in the hero lockup.
  • Don't set the wordmark in a system serif or capitalise it. Rounded, heavy, lowercase.

Contrast, decided once

Teal is a beautiful accent and a bad ink: on cream it manages 2.5:1, so it never carries wording. Two derived tokens settle it for good — --accent-ink (#0a6e8f, 5.1:1 on cream) for accent-coloured text and links, and --on-accent (navy, 5.1:1 on teal) for text sitting on a teal button. White on teal fails at 2.8:1 and is never used.

The three channels

Button 1 left, 2 centre, 3 right — yellow, coral, teal, taken straight from the mark and colour-coded on the enclosure, so the same colours identify a button everywhere else: the contact rows in the admin panel, the lenses in the simulator, the lamps below. A channel colour never means anything other than "this button".

3 · Typography

The brand asks for a chunky rounded geometric sans. ui-rounded is SF Pro Rounded on Apple platforms — exactly that letterform, for zero bytes — with Nunito, Quicksand and Varela Round as named fallbacks and system-ui underneath. No webfont on purpose: the setup page is served from a Pi Zero over its own hotspot, and a font that arrives late is a page a parent stares at.

5 · Light signature

The device has no screen, so light is its entire vocabulary — this is the most important page in the kit. The ladder is per-LED and first match wins; the authority is src/core and the ladder in docs/architecture.md, and these lamps are a picture of it. Solid is the language of error. Nothing here has a chime attached, because the hotspot can come up at 3am when the router dies.

  • Booting A chase, left to right. Held for 2.6s or nobody would ever see it.
  • Connecting All three together, slowly. Something is happening and it is not done.
  • Setup hotspot is up A double-pulse: 150ms on, off, on, then dark. Ranks above the Wi-Fi error, because "setup is waiting for you" is the part a parent can act on.
  • Wi-Fi is down All three solid. Solid means error, always, and nothing else does.
  • WhatsApp is unlinked Lamps 1 and 2 solid — the same language, a different word.
  • A message is waiting That button blinks, 0.8s on, 0.8s off, in its own colour. Tap it to hear it.
  • Silent mode just changed One slow left-to-right pass, 0.5s per lamp, once. It is the only thing silent mode ever shows: while it is on the box looks exactly like an idle box.
  • Idle, nothing to say Dark, silent mode included. A box in a child's bedroom at night is allowed to be dark.

6 · Voice

Every word in the product is read by a parent, usually while a child is pulling at their sleeve. Say what is happening, in the order it matters, and never make them diagnose anything.

  • Plain and warm "Let's get this on your Wi-Fi." Not "Network configuration".
  • Say what will happen "This page will stop working — that is what success looks like."
  • Name the real cause "That settings password was not right", not "Unauthorized" — the generic message sends a parent looking at the wrong field.
  • No baby talk to adults The child never reads a word of this. The parent is a competent adult in a hurry.
  • No jargon on the portal No "PSK", no "SSID" alone, no "captive portal". Cards, steps, and the name of their network.
  • No cheerful blame "Oops! Something went wrong" tells nobody anything. Print what the device said.

7 · Tokens

The full list lives in public/shared/tokens.css, which is the only file in the repository allowed to contain a colour literal. Reference the semantic name, never the brand name — var(--accent), not var(--brand-teal) — so dark mode and any future retheme stay one file's problem.

Token Role
--bg --surface --surface-sunken Page, raised card, recessed input
--text --muted Body ink, and secondary ink that still passes AA (4.7:1)
--border --border-strong Divider, and the edge a control's travel is drawn with
--accent --accent-ink --accent-deep --accent-soft --on-accent Teal as fill, as text, as pressed edge, as tint, and what sits on it
--warm --pop Yellow and coral, for emphasis that is not an action
--danger --danger-soft Error ink and its background. Never coral — coral is a brand accent
--ch-1…3 --ch-1-off…3-off The three buttons, lit and unlit
--device-body --device-body-top --device-edge --device-ink The enclosure the simulator paints. Outside the dark-mode block: a physical object does not repaint itself because a laptop did
--font-display --font-body --font-mono Rounded chunky for headings and controls, system UI for prose
--text-xs … --text-display Seven steps. If a size is not here, it is not a size
--tracking-display --tracking-wordmark --tracking-label Headings, the wordmark (tighter still), and small-caps labels (looser)
--space-1 … --space-12 4px-based spacing
--radius-sm --radius-md --radius-lg --radius-pill 8 / 12 / 18 / pill. Nothing in this brand has a sharp corner
--tap 3rem. The floor for anything a standing parent has to hit
--dur --dur-fast --ease Motion, and zero under prefers-reduced-motion
